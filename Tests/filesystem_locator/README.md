# Filesystem 文件定位符主机测试

本目录经 Filesystem Service 的公开入口验证文件定位符：`Service_Filesystem_ReadDirectory` 随目录条目给出定位符，`Service_Filesystem_OpenFileByLocator` 按它打开文件。不直接断言 `ff.c` 内部。

## 被测对象与替身

- 链接真实的 Filesystem Service（服务、文件、目录、路径、句柄、状态映射和定位符打开）与 FatFs（`ff.c`、`ff_gen_drv.c`、`diskio.c`、`cc936.c`），配置取自仓库 `FATFS/Target/ffconf.h`（CMake 复制并去掉 MCU 头）；**`_FS_LOCK` 取产品值（9）**：Service 的静态断言要求 `_FS_LOCK` 不小于槽总数，所以经 Service 永远填不满锁表；“锁表满”用例改成把锁表其余的项直接用 FatFs 占满（用 `ff.h` 里的 `_FS_LOCK`，不依赖具体数值），因此产品值随 CubeMX 导出变化也不影响本测试。FreeRTOS 头与互斥锁来自共用桩 [`Tests/stubs/freertos/`](../stubs/freertos/README.md)，持锁统计依赖的周期计数器与 Service Log 来自 [`Tests/stubs/lock_env/`](../stubs/lock_env/lock_env_stub.h)。
- **`ff.c` 是构建目录里的副本**：CMake 把仓库的 `ff.c` 复制并统一成 LF，再用 `git apply` 应用 `patches/fatfs/` 下的补丁（副本已含该补丁则跳过）。测试因此不依赖工作树里的 `ff.c` 是否已被用户打上补丁；补丁无法应用到当前 `ff.c`（上游变了）时配置阶段直接失败。
- 介质是 `ram_disk.c`：2 GiB 的稀疏 RAM 盘，只替代 FatFs 的磁盘驱动接口并统计读扇区次数；SD/Flash 传输层的四个符号由测试文件里的最小替身提供。

## 覆盖

镜像：32 KiB 簇的 FAT32，`Music/` 里 12000 首随机长名（22 到 59 个字符，平均约 4.4 个目录项）、每首 8 到 104 字节的确定内容。

- 第 1 首与第 12000 首按定位符打开读出的内容，与按路径打开、与生成时的预期一致。
- 12000 首**每一首**都带可用的定位符且读出内容正确（覆盖主目录项落在扇区末尾、簇末尾的位置）。
- 读扇区数：第 1 首为 1；最后一首只比“目录占用的簇数”多一点（沿簇链走到目标簇，每个目录簇至多一次 FAT 扇区读）；按路径打开最后一首要读完全部目录扇区（数千个），两者差一到两个数量级。**注意读扇区数不是严格的常数**：它随目标所在的目录簇序号增长（每簇至多一次），不随目录项数线性增长。
- 篡改被拒（返回“核对不符”，不返回句柄、不占文件槽）：全零定位符、起始簇不符、长度不符、位置指向别的目录项、位置落在长名项上、位置越界或未对齐、文件夹簇错误；子目录条目的定位符；文件被删除后的旧定位符。
- 入口加锁：按定位符打开拿 SD 卷锁一次，其中 `f_open_dirent` 一步在表锁内（卷锁 → 表锁）；全零定位符占槽后立刻判核对不符，没走到表锁；长度不符走到补丁函数、核对失败后表锁照样放掉；关闭不碰表锁；表锁被占时调用者在已持卷锁时等表锁；拒绝名单里的任务按定位符打开在等锁之前停机。
- 锁：按定位符打开与按路径打开登记同一把 FatFs 锁（同一文件两种方式共存只增读计数）；锁表满时失败而非误报核对不符；写方式持有时按定位符只读打开失败（`SERVICE_BUSY`）；全部关闭后锁释放；`CloseFile` 返回 OK，关闭后旧句柄失效。
- 定位符打开的文件是正常只读文件：大小、位置、Seek、读回正确，写入被拒。

## 保真边界

PASS 只证明补丁函数与 Service 入口在内存镜像上的行为。不证明 SD 卡上的耗时、真实卡的簇布局（目录簇在 FAT 中的分布影响簇链上的 FAT 扇区读数）、`Storage` 对三态结果的使用（改用定位符票），也不证明工作树里的 `ff.c` 已打补丁——后者由 `scripts/apply-vendor-patches.ps1 -Check`（FAST）与固件链接保证。

从仓库根目录运行：

```powershell
./scripts/test-host.ps1 -Module filesystem_locator
```

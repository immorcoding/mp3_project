# 内存目录下 f_open 的 CPU 耗时实测（#170 调研）

- 票：immorcoding/mp3_project #170「内存目录下 f_open 的 CPU 耗时实测」，父图 #160；解锁 #167（打开文件提速的做法与边界）。
- 日期：2026-10-30。基线：`origin/main` bcc086e。
- 问题：若目录扇区全部由 RAM 供给（自维护 SD diskio 层里的扇区缓存，不改 FatFs），`f_open`（`follow_path` → `dir_find`）本身还要花多少 CPU 时间？扇区缓存够不够，还是必须给 `ff.c` 加按目录项位置打开的函数。
- 本文只记录事实、推算与待测项，不选路线。

证据标记：
- 【实测·主机】在本机 x86 上用仓库未修改的 `ff.c` 跑出的数。
- 【实测·指令】把同一份 `ff.c` 交叉编译成 Cortex-M7 Thumb-2，在 Unicorn 的 M7 模型里逐指令执行得到的指令数（精确的动态指令数，不含周期）。
- 【推断】由上两者加假设换算出的 STM32H743 数，必须上板确认。
- 【假设】取值依据在文中写明、未经板测的参数。

## 0. 结论摘要

1. 【实测·指令】12000 个文件、平均 4.58 项/文件的中文长名目录里，打开最后一个文件的 `f_open` 共执行约 **949 万条** Thumb-2 指令（8 个相邻目标的均值，范围 772–1120 万），其中 `ff_wtoupper` 占约 59%，`dir_find` 24%，`dir_next` 12%，`move_window` 5%。同时发出 3492 次 `disk_read(count=1)`。
2. 【推断】换算到 480 MHz 的 H743：纯 CPU 约 **20–30 ms**（CPI 1.0–1.5），加上 3492 次缓存命中的扇区拷贝（每扇区 2.6–5.1 μs，【假设】）约 **10–19 ms**，合计 **30–49 ms**。**达不到「单次 ≤ 约 30 ms」，位置 12000 处恰在目标线上方或贴线。** 位置 6000 约 15–24 ms，位置 1000 约 3–5 ms。
3. 【推断】队列界面一窗 12 行：在末尾 12 个文件处约 0.36–0.58 s，对 ≤ 0.5 s 的目标是贴线；窗口落在目录中部时（位置约 6000）约 0.18–0.29 s。
4. 【实测·指令】**经 8.3 别名（`altname`）打开不比长名省**：别名路径在 12000 处 962 万条，长名 949 万条。本仓库 R0.12c 的 `ff.c` 只在 `dir_register` 内部设 `NS_NOLFN`（ff.c:2337），`create_name` 不设，所以 `dir_find` 对别名路径照样对每个文件的首个 LFN 项调用 `cmp_lfn`。
5. 【实测·指令】对照镜像（12000 个全 8.3 文件，1 项/文件）末尾 116 万条指令、762 次 `disk_read`，【推断】约 **4.6–7.7 ms**，达标。**4.4 项/文件的长名目录比 1 项/文件的 8.3 目录贵约 8 倍，其中约 4.6 倍来自项数，其余来自 LFN 比较。**
6. 【实测·指令】`ff_wtoupper`（`option/cc936.c`，线性扫描 `cvt2` 表）是最大的单项：CJK 字符每次调用约 300 条指令。【实测·指令】若假设它对 U+3000–U+A63F 直接返回（逐值核对与原实现无差别，仅为实验，不是建议），12000 处降到 429 万条指令，【推断】约 **19–32 ms**。
7. 【实测·主机】目录 RAM：12000 首、55005 个目录项 = **1.68 MiB（3437 个扇区，54 个 32 KiB 簇）**，与 1.7 MB 估算一致；8.3 对照 0.37 MiB（750 扇区）。

## 1. 方法与构建（对应票「做法」第 1 条）

仓库没有主机 FatFs 测试之外的基础设施，沿用 `Tests/flash_ftl/CMakeLists.txt` 的做法：复制 `FATFS/Target/ffconf.h`，只剥掉其中 `main.h`、`stm32h7xx_hal.h`、`bsp_driver_sd.h` 三个 MCU/BSP 头文件 include（运行时生成到临时目录，不改仓库文件）。

| 项 | 取值 |
|---|---|
| 被测源码 | `Middlewares/Third_Party/FatFs/src/ff.c` 与 `option/cc936.c`，未修改，与固件 `cmake/stm32cubemx/CMakeLists.txt` 链接的一致 |
| 配置 | 未修改的 `FATFS/Target/ffconf.h`：`_USE_LFN 1`、`_LFN_UNICODE 1`、`_CODE_PAGE 936`、`_FS_EXFAT 0`、`_FS_LOCK 2`、`_FS_REENTRANT 0`、`_FS_NORTC 1`、`_MAX_SS 512` |
| diskio | `ramdisk.c`：稀疏 RAM 镜像（64 KiB 一页，未写入的页读出 0），统计 `disk_read` 调用与扇区数 |
| 主机桩 | `_FS_REENTRANT 0`、`_FS_NORTC 1`，不需要 `get_fattime`、`ff_memalloc` 与同步函数；无需桩 |
| 主机编译 | gcc 15.1.0（MinGW-w64），与固件相同的 `-Os`，另跑 `-O2`；加 `-DUNICODE`（否则 integer.h 在 `_WIN32` 下引入的 `tchar.h` 让 `TCHAR` 成为 `char`，与固件 `_LFN_UNICODE=1` 的 UTF-16 不符） |
| 固件构建级别 | Release：`-Os`（`cmake/gcc-arm-none-eabi.cmake:35`）；Debug 为 `-O0`。ST clang 预设为 `-Oz`，非默认 |
| 主机 CPU | AMD Ryzen 7 8745H（标称 3.8 GHz，实际加速更高）；线程固定在一个核，最高优先级 |

镜像：
- FAT32，`f_mkfs(FM_FAT32|FM_SFD, au=32768)`，簇 32 KiB（16–32 GB 卡常见值，【假设】），共 62332928 扇区（#143 的 30436 MB 卡）。目录 `Music/` 由 `f_open(FA_CREATE_NEW)` 逐个创建 12000 个零长度文件，所以**目录顺序 = 创建顺序**（程序用 `f_readdir` 逐项核对）。
- 镜像 A（长名）：形如 `歌手名 - 曲名.mp3` 的 UTF-16 名，总长在 22–59 码元均匀，70–75% 为 GBK 内可转换的 CJK 字符、其余 ASCII，伪随机固定种子。实测 **55005 项 / 12000 文件 = 4.584 项/文件**（票的目标约 4.4；略长，偏保守）。FatFs 自生成 `XXX~1.MP3` 形别名。
- 镜像 B（对照）：`TR000000.MP3`…，全大写 8.3，1 项/文件。

## 2. 主机实测（对应票「计量」）

每个目标取中位数（101 次重复），每个位置取其及其前共 K=40 个文件的均值（长名里单个名字的字符构成对结果影响很大，见第 3 节，所以不用单文件）。「扣钩子」= 减去 `disk_read` 钩子自身开销（实测 0.009 μs/次，可忽略）。全表见 `docs/research/fatfs-open-cpu-cost/` 脚本输出，此处节录。

【实测·主机】`-Os`，μs（均值；括号为 40 个目标的最小–最大）：

| 位置 | 其前目录项数 | 长名路径 | 8.3 别名路径 | `disk_read` 次数 | 8.3 对照镜像（名字路径） |
|---|---|---|---|---|---|
| 1 | 0 | 3.0 | 2.5 | 2 | 0.4 |
| 1000 | 4544 | 58.6（41–72） | 58.5 | 290 | 6.3（980 项，63 次） |
| 6000 | 27391 | 368.7（271–454） | 350.1 | 1740 | 34.0（5980 项，380 次） |
| 12000 | 54911 | 758.3（574–914） | 750.2 | 3487 | 63.1（11980 项，761 次） |

补充：
- 每个位置的 `disk_read` 数 ≈ 其前目录项数 / 16 + 少量（每 32 KiB 簇边界读一次 FAT 扇区），全部 `count=1`，没有预读，与 #162 的结论一致。
- `-O2` 反而更慢（长名 12000 处 917 μs，对照 46 μs；`cmp_lfn` 的代码生成不同，非噪声，重复三次一致）。固件用 `-Os`，以 `-Os` 为准。
- 主机上每目录项斜率：长名约 13.9 ns/项（(758−59)/(54911−4544)），对照 5.2 ns/项。在更高位置略有上翘（1.7 MiB 的镜像超出主机 L2，主机内存效应），**所以主机时间只用作量级校验，H743 换算以第 3 节的指令数为准**。
- 8.3 别名路径与长名路径的均值几乎相同，原因见摘要第 4 点；别名路径 40 个目标的离散很小（别名全为 ASCII，比较便宜），长名路径的离散大。

## 3. 指令数（对应票「换算」的基础）

主机时间含 x86 缓存效应，且无法直接外推 M7。所以把同一份 `ff.c`/`cc936.c`/`ffconf.h` 用 `arm-none-eabi-gcc 15.2.1 -mcpu=cortex-m7 -mthumb -Os` 编译，在 Unicorn 2.1.4 的 Cortex-M7 模型里逐指令执行，截获 `disk_read` 入口并由同一镜像供数（等价于全命中缓存），数 `f_open` 区间内的指令数（`ff.c`+`cc936.c` 的 `.text` 约 10.8 KB，`-Os`）。每个位置取 8 个相邻目标。只数指令与已取分支，不建模流水线、cache、等待状态。

【实测·指令】f_open 指令数（均值；括号为 8 个目标的最小–最大）：

| 位置 | 长名 | 8.3 别名 | 长名 + CJK 快速路径（实验） | 8.3 对照镜像 | `disk_read` 次数（长名） |
|---|---|---|---|---|---|
| 1 | 40 011 | 33 135 | 9 543 | 5 151 | 2 |
| 1000 | 94.5 万（77–106 万） | 94.9 万 | 36.8 万 | 11.4 万 | 294 |
| 6000 | 480 万（394–529 万） | 486 万 | 216 万 | 62.1 万 | 1744 |
| 12000 | **949 万（772–1120 万）** | 962 万 | 429 万 | 116 万 | 3492 |

- 斜率（位置 1000→12000）：长名 约 **170 条指令/目录项**（约 780 条/文件）；快速路径实验 约 78 条/项；8.3 对照 约 95 条/项（SFN 项 `dir_find` 与 `dir_next` 的固定开销）。
- 位置 1 的 4 万条指令几乎全是匹配时的整串 `cmp_lfn`（每个字符调两次 `ff_wtoupper`），与位置无关，是一个常数项。
- 长名目录的指令数**随目标文件名的字符而变**，8 个相邻目标之间差 ±20%：`cmp_lfn` 对每个候选文件都调用 `ff_wtoupper(目标名在偏移 (ord-1)×13 处的字符)`，目标名该处是 CJK 时每个候选多花约 300 条指令。所以任一具体文件的耗时与其名字相关，上表是均值。
- 热点函数占比（12000，长名）：`ff_wtoupper` 59%、`dir_find` 24%、`dir_next` 12%、`move_window` 5%。

`ff_wtoupper` 为什么贵：`cc936.c` 里的实现对 U+1000 以上字符线性扫描 `cvt2` 压缩表直到命中范围，CJK（U+4E00–U+9FA5）要扫过表里所有更低范围的条目，约 300 条指令/次；ASCII 大写与数字在第一个范围条目前即返回，约 8 条。因此**曲库里 CJK 越多越贵**，纯 ASCII 英文名更便宜；本文的名字 70–75% 是 CJK，对中文曲库是偏真实的，对英文曲库偏贵。

## 4. 换算到 STM32H743（对应票「换算」）【推断】【假设】

### 4.1 时钟与存储位置（仓库内确认）

- SYSCLK = PLL1：HSE 25 MHz（`stm32h7xx_hal_conf.h` 的 `HSE_VALUE`，板上晶振是否 25 MHz 【未核对】）÷5×192÷2 = **480 MHz**，`SYSCLKDivider = DIV1`，AHB 240 MHz（`Core/Src/main.c:168–188`）。I-cache、D-cache 均在 `main.c:90–93` 打开。
- 代码在 FLASH（0x08000000，`STM32H743xG_flash.ld` 的 `.text >FLASH`），热循环很小，取 I-cache 命中。
- `.bss`（含 `FATFS SDFatFS` 及其 512 B 窗口，`FATFS/App/fatfs.c:18`）在 DTCM（ld `.bss >DTCMRAM`），零等待数据访问。`FIL`/`DIR` 的存放位置 【未核对】。
- SDRAM：FMC Bank1，16 位，CAS 3，SDCLK = FMC 内核时钟 PLL2R（25/5×104/2 = 260 MHz）÷2 = **130 MHz**（`Core/Src/fmc.c:109–118`，`main.c:212–216`；`fmc.c` 注释提到 32 MHz 临时访问，终值以运行时配置为准，【未核对】）。MPU 将 0xC0000000 起 32 MB 设为可缓存（`main.c:245–262`），拷贝会走 D-cache 行填充。

### 4.2 CPU 时间

方法：H743 时间 = 指令数 × CPI ÷ 480 MHz。CPI 取 **1.0–1.5**【假设】：Cortex-M7 双发射顺序核、热循环在 I-cache 与 DTCM、分支预测器在位，但 `dir_find` 的 LFN/SFN 项交替造成分支预测失误、`push/pop` 多寄存器指令与 load-use 停顿。无板测，故给范围，不给点值。2.08–3.13 ns/指令。

交叉校验：主机 12000 处 758 μs / 949 万条 ARM 指令 ≈ 80 ps/条，M7 为 2083–3125 ps/条，即主机到 M7 约 26–39 倍。主机核（约 4–5 GHz、IPC 3–4）对 M7（480 MHz、IPC 0.7–1）的量级之比与此相符。这只是量级校验，不独立。

### 4.3 一次缓存命中的 `disk_read` 的调用开销

每个目录扇区仍是一次 `move_window` → `sync_window`（检查脏位）→ `disk_read(count=1)`。缓存命中时开销是：（a）自维护 diskio 层里的查找与分发，估 40–80 条指令 ≈ 0.1–0.3 μs（`SD_read`→缓存查找，现有 `SD_read` 里还有 `BSP_SD_GetCardState` 轮询，缓存命中应跳过）；（b）把 512 B 从缓存拷进 `fs->win`（DTCM）。

拷贝成本取决于缓存放在哪里。全目录缓存 1.68 MiB 超过 AXI SRAM（RAM 512 KB，其中还有 SDMMC DMA 缓冲），只能放 SDRAM：
- 16 位 SDRAM 130 MHz 的峰值带宽 260 MB/s；按 D-cache 32 B 行填充（每行 16 拍加首拍延迟）实际约 100–200 MB/s【假设】，即 **512 B ≈ 2.6–5.1 μs**。目录扫描是顺序读，M7 没有数据预取，行填充串行；使用 MDMA 拷贝不改变 `ff.c` 同步等待的事实。
- 因此每次缓存命中的 `disk_read` ≈ **2.9–5.4 μs**（含 0.3 μs 分发）。**这与 CPU 时间同量级，不是可忽略的。** 12000 处 3492 次共 10–19 ms。
- 对比：现状经 SD 的单扇区读按 #162 估为 0.2 ms 量级（未测），缓存把每扇区代价降低约两个数量级，但不降到零。

### 4.4 STM32H743 估计表【推断】

CPU = 指令数 × (2.08–3.13 ns)；拷贝 = `disk_read` 次数 × (2.9–5.4 μs)。单位 ms。

| 位置 | 路径 | CPU | 缓存拷贝 | 合计 | 12 次连续（末尾窗口） |
|---|---|---|---|---|---|
| 1 | 长名 | 0.08–0.13 | 0.01 | 约 0.1 | 约 1–2 |
| 1000 | 长名 | 2.0–3.0 | 0.9–1.6 | **2.8–4.5** | 34–54 |
| 6000 | 长名 | 10.0–15.0 | 5.1–9.4 | **15–24** | 0.18–0.29 s |
| 12000 | 长名 | 19.8–29.7 | 10.1–18.9 | **30–49** | 0.36–0.58 s |
| 12000 | 8.3 别名（LFN 目录中） | 20.0–30.1 | 10.1–18.9 | **30–49** | 0.36–0.59 s |
| 12000 | 长名，CJK 快速路径（实验） | 9.0–13.4 | 10.1–18.9 | 19–32 | 0.23–0.39 s |
| 6000 | 8.3 对照镜像 | 1.3–1.9 | 1.1–2.1 | 2.4–4.0 | 29–48 |
| 12000 | 8.3 对照镜像 | 2.4–3.6 | 2.2–4.1 | **4.6–7.7** | 56–93 |

- 12000 处长名的 8 个目标之间 CPU 指令数差 ±20%（772–1120 万），对应 CPU 16–35 ms，所以逐个文件的分布更宽：不排除个别文件超过 49 ms。
- 「12 次连续」按每次都在同一个位置计，是上限；窗口 12 行取的是相邻文件，位置基本相同。
- 以上都不含 `f_open` 之外的开销（`f_close`、`inc_lock` 等对 `_FS_LOCK 2` 为常数，指令数已含 `f_open` 内的部分）。

## 5. 直接回答票的问题

在单文件夹 12000 首、平均 4.58 项/文件的中文长名目录里，所有目录扇区由 RAM 供给：

1. **最后一个文件的单次 `f_open`：约 30–49 ms**（CPU 20–30 ms + 缓存拷贝 10–19 ms，【推断】）。**不能稳定满足 ≤ 约 30 ms**，贴线甚至超出。中部（位置约 6000）约 15–24 ms 满足；位置 1000 约 3–5 ms。
2. **长名与 8.3 别名：无差别**（30–49 ms vs 30–49 ms）。别名不是捷径。
3. **全 8.3 单项目录：约 5–8 ms**，满足；它只在目录是 1 项/文件时才成立，长名曲库不具备这个前提。
4. **一窗 12 行 ≤ 约 0.5 s：** 位于目录末尾 0.36–0.58 s，贴线；位于中部 0.2–0.3 s，满足。
5. **与位置无关：不成立。** 耗时随其前的目录项数线性增长（约 170 条指令/项、每 16 项一次 `disk_read`），位置 1 约 0.1 ms，位置 12000 约 30–49 ms。扇区缓存只是把每个扇区的 SD 代价（约 0.2 ms 量级，未测）换成约 3–5 μs，常数因子下降，斜率仍在。
6. **全目录扇区缓存的 RAM：** 【实测·主机】55005 项 × 32 B = **1.68 MiB（3437 扇区）**，加 54 个簇的 FAT 链所在的 1–2 个 FAT 扇区与根目录扇区，约 1.7 MiB；这是 4.58 项/文件的结果，按票的 4.4 项/文件为 12000×4.4×32 = 1.69 MB，一致。全 8.3 为 0.37 MiB。必须放 SDRAM（AXI SRAM 只有 512 KB）。

## 7. 对后续决定的含义（不选路线）

- 扇区缓存（不改 FatFs）能把单次打开压到约 30–49 ms（最坏位置）、中部约 15–24 ms，**在 12000 首的长名中文目录里，末尾位置在 ≤ 约 30 ms 的目标线上或其上方**；它不消除对位置的依赖，只降低斜率。
- 其中一半以上的 CPU 来自 `option/cc936.c` 的 `ff_wtoupper` 线性表扫描；它在 Vendor 目录中，与改 `ff.c` 同样受 Vendor 规则约束。把 CJK 区短路（实验，已核对与原实现逐值一致）可使末尾位置降到约 19–32 ms，仍随位置增长。
- 无论是缓存还是 CJK 加速，剩下的斜率来自 `ff.c` 每次从目录第 0 项扫描；位置无关只能靠按目录项位置直接打开（#162 路线 a）或把单目录扫描上界降下来（路线 d）。本文不评价它们。
- 若采用扇区缓存，除 1.7 MiB SDRAM 外还要决定：缓存的填充时机（扫描时一遍读入）、与目录变更（增删文件）的一致性、`sd_diskio.c` 的 `SD_read` 里 `BSP_SD_GetCardState` 轮询的绕开。
- 全 8.3 的单项目录约 5–8 ms 满足目标，但曲库实际是 4+ 项/文件的长名，不能直接套用。
- 8.3 别名路径是死路：在本仓库的 R0.12c 上它既不减少 `disk_read`，也不减少 `cmp_lfn`。
- 待板测（`hw:pending`）：CPI（`DWT->CYCCNT` 包 `f_open`，在 SDRAM 缓存全命中或把目录页预读进 DTCM 的条件下）、SDRAM→DTCM 的 512 B 拷贝耗时、真实曲库的 CJK 占比与 `f_open` 位置曲线。

## 8. 复现

```powershell
# 主机计量（-Os 为固件级别；-Opt O2 另测；-Fast 为 ff_wtoupper 的 CJK 快速路径实验）
./docs/research/fatfs-open-cpu-cost/run.ps1 -Opt Os
./docs/research/fatfs-open-cpu-cost/run.ps1 -Opt O2
./docs/research/fatfs-open-cpu-cost/run.ps1 -Opt Os -Fast

# Cortex-M7 指令数（需 arm-none-eabi-gcc 在 PATH，且 `pip install unicorn`；约 4 分钟；须先跑过同 -Opt/-Fast 的 run.ps1）
./docs/research/fatfs-open-cpu-cost/run_arm.ps1 -Opt Os
./docs/research/fatfs-open-cpu-cost/run_arm.ps1 -Opt Os -Fast
```

文件：`docs/research/fatfs-open-cpu-cost/`：`bench.c`（镜像生成与计量）、`ramdisk.c/.h`（RAM diskio）、`hostclock.c/.h`（计时）、`fastupper.c`（实验）、`arm_emu/`（`harness.c`、`link.ld`、`emu.py`）、`run.ps1`、`run_arm.ps1`。所有产物写入 `%TEMP%`，不进仓库。名字由固定种子生成，重跑得到相同镜像与指令数；主机 μs 随机器而变。

局限：Unicorn 是功能仿真，不模拟 M7 周期；目录只含 `.mp3` 零长度文件（不含 APIC、子目录、已删除项）；已删除项与长度 >59 码元的名字未覆盖；镜像 A 在创建过程中 FatFs 为长名生成的 `~N` 别名可能带哈希后缀，别名路径的比较成本取决于此。

# ADR-0015：卷分工、曲库扫描与资源安装暂存

- 状态：已接受。曲库扫描与顺序播放列表已实施；设备侧 Resource Pack 安装未实现。
- 日期：2026-09-03
- 修订：2026-09-04。取消用 Flash 存歌；曲库条目不再保存来源卷。
- 相关决定：[ADR-0009](0009-w25q256-firmware-slots-and-diagnostic-reservation.md)、[ADR-0013](0013-usb-msc-product-scope.md)、[ADR-0014](0014-filesystem-volume-aware-file-interface.md)
- 技术事实：[catalog_architecture.md](../catalog_architecture.md)

## 背景

设备已同时具备 SD FatFs 与 Flash FTL FatFs，且 Resource Pack 以原始只读镜像驻留在 FTL 之前。当前不提供 USB MSC，用户用读卡器向 SD 放入内容。需要明确：歌放在哪、Flash 卷做什么、壁纸与小模型如何更新才不会在拔卡后消失。曾考虑过用 Flash 作第二音乐库，因而要求曲库条目带来源卷；该路线已取消。

## 决定

**SD 是用户音乐的唯一库。** 批量导入仍用读卡器。首版只扫描已挂载 SD 上的 `Music/`，按目录项顺序生成一条播放列表；没有该目录或未插卡则列表为空，不自动创建目录，也不扫描卡根。Flash 卷不纳入曲库扫描，也不再作为歌曲存放处。曲库条目只存 UTF-8 相对路径。Filesystem 文件/目录接口仍带 Volume：那是文件 API 的卷选择，不是曲库行字段。

**Flash FTL 不是音乐库。** 它是机内可写磁盘：可选的书、设置类小文件，以及资源安装的暂存。固件槽、自检扇区和 Resource Pack 仍不经过 FTL 或 FatFs。不为了证明 FTL 有用而向内部盘拷歌，也不做 SD→Flash 的专用拷贝工具充当导入手段。

**生效中的壁纸、字库、小模型只认机内 Resource Pack。** 用户可以把安装包放在 SD 上，Settings 发起更新。安装不得从 SD 边读边烧 Pack。约定路径（设备侧尚未实现）：

1. 整包拷入 FTL 暂存文件并校验（头与 CRC）；
2. 仅当暂存完整且校验通过后，才退出映射并按 Pack 协议写入资源区，再校验；
3. Pack 生效后删除暂存。

暂存失败或中途拔卡：Pack 不改，沿用旧资源。Pack 写入失败：保持旧 Pack，暂存仍在，不插卡也可重试写入。状态由 Storage Task 推进，GUI 只显示阶段。壁纸虽小、可整包进 SDRAM，仍与模型共用「先机内暂存、再写 Pack」的状态机，避免两套安装。

**以后的资源管理器**只做只读浏览与跨卷 `Copy`/`Move to` 用户文件（歌、书）。它不是 Pack 安装入口。`Update/` 一类暂存路径不属于曲库扫描。

**曲库与播放列表分开，且都不把整表指针交给 GUI。** 曲库是已扫描路径的事实表。播放列表是曲库下标的排列；首版为目录顺序的恒等序列，长度为当时的曲库条数。Storage Task 在挂载扫描成功后先建曲库再建播放列表，拔卡一并作废。当前公开 API 只有建表与作废。以后若增加问询：必须带代次（播放列表记下对应的曲库代次，0 表示已作废）；Queue 只取可见行，预取的是行文本不是解码缓冲；上一首/下一首沿播放列表下标；随机或心动模式只换下标序列，不重扫盘。

## 不采用的方案

- **两卷一起扫 Music / 用 Flash 存歌：** 没有导入途径时只会多出空的本机分区；产品已取消该路线。
- **曲库行保存来源卷以便以后加卷：** 音乐只在 SD，加卷再改模型，避免为首版未用的卷字段付代价。
- **从 SD 直接编程 Resource Pack：** 拔卡或读失败可能留下半截系统资源。
- **把壁纸/模型当 FTL 里的普通图片或文件供 GUI 长期引用：** 与 Pack 映射及启动加载契约不一致；拔卡安全应用 Pack 解决，不是用 FTL 当生效位置。
- **用日志式双队列传递整目录指针：** 卸载后悬空，也无法服务分页与播放队列。
- **恢复 USB MSC 或写 SD→Flash 灌歌工具：** 与 ADR-0013 及「歌在卡上」的用法冲突。

## 后果

- 曲库 / 播放列表首版只依赖 SD 挂载与 `Music/` 目录枚举；实现细节见 [catalog_architecture.md](../catalog_architecture.md)。
- Resource Pack 的设备侧更新以 FTL 暂存为事务缓冲（未实现）；PC 烧录仍是发布默认包的路径。
- Filesystem 保持卷感知；跨任务扫描与安装命令尚未实现，不得由 GUI 直接调用同步文件接口。
- 实现资源管理器或 Pack 安装时另开 Interface，不把两者做成同一种 `Move to`。

# ADR-0011：FTL 整组异地提交与扫描恢复

- 状态：已接受、已实施；主机回归与固件构建通过，硬件验收待完成
- 日期：2026-08-31
- 技术方案：[Flash FTL 首版设计](../shape/storage.md#durability)
- 相关决定：[ADR-0001](0001-w25q256-component-seams.md)、[ADR-0009](0009-w25q256-firmware-slots-and-diagnostic-reservation.md)

## 背景

NOR 擦除粒度大于逻辑扇区。原地读改擦写会在断电时丢失旧数据；逐小扇区独占擦除块容量效率低，混合多个独立记录又增加回收搬迁与恢复复杂度。首版需要可验证的掉电语义和较高容量利用率。

## 决定

多个逻辑扇区合为一组，一个组版本独占物理擦除块，保留头和最后写入的提交记录。新块数据与提交均验证后才切换 RAM 映射，保留旧块直到此时。分组尺寸、字段与容量参数由技术文档维护。

不采用 RAM 写回早确认；上电扫描持久化记录重建映射和块状态。最新已提交版本损坏时报错，不静默回退；只保证定义故障模型内单组更新，不承诺跨组或 FatFs 整文件事务原子性。

未映射扇区返回 NOR 擦除值；确认擦除的新块可跳过全擦除值页编程，但仍校验。旧组版本整块失效，普通 GC 无需搬迁混合有效记录。空闲预算全池循环使用，首版不做静态磨损均衡或持久化寿命计数。

格式化使用双卷描述和新格式代次，先持久化准备阶段再破坏性擦除，最后记录就绪；新准备状态不能被旧就绪状态掩盖。挂载失败、不兼容和格式化中断不触发自动格式化；运行故障先停止、安全收尾，再显式恢复扫描。

## 不采用的方案与后果

- 不原地覆盖有效块，代价是整组重写与空闲预算。
- 不逐小扇区独占擦除块，以提升容量效率，代价是组内写放大。
- 不采用复杂混合日志与静态磨损均衡，降低 GC/恢复复杂度，但不保证冷热数据均匀磨损。
- 不持久化完整映射检查点，代价是启动扫描和校验耗时。
- CRC 不能替代断电验收，也不能声称无碰撞。
- 格式、分区或容量改变需兼容性检查与明确迁移/重格式化，不静默重解释旧盘。

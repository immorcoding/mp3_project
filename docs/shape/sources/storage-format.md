# FTL v1 介质格式

STOR-4/5/11/13 的持久化来源材料；算法选择理由为 [ADR-0011](../../adr/0011-ftl-copy-on-write-and-recovery.md)，接口和实现入口为 [FTL README](../../../Components/flash_ftl/README.md)。本表用于解析已有介质，不是配置默认值清单。

| 协议项 | v1 定义 |
| --- | --- |
| 几何 | 512 B 扇区，七扇区一组；每组版本独占 4096 B 擦除块，头0..255、数据256..3839、提交3840..4095 |
| 容量 | 物理块N，数据块D=N−2，预留R=ceil(D×预留百分比/100)，逻辑组G=D−R，逻辑扇区7G；容量/预留变化影响卷兼容，GC水位不改变格式 |
| 编码 | 小端逐字段；未用字节0xFF；元数据页256 B，CRC@252..255覆盖0..251 |
| CRC | 反射CRC32多项式0xEDB88320、初始0xFFFFFFFF、结果取反；每个数据CRC覆盖完整512 B扇区 |
| 常量 | 卷magic=0x314C4F56，头=0x31524746，提交=0x31544D43；format=1，PREPARING=1，READY=2 |
| 卷页 | 双卷块各以页0存PREPARING、页1存READY；普通写不改卷页 |
| 计数 | epoch从1起、每次显式格式化递增；组版本从1起、0无效，到UINT64_MAX拒绝继续 |

| 记录 | 字段偏移；未标宽度均u32 |
| --- | --- |
| 卷阶段页 | magic@0，format@4，epoch:u64@8，phase@16，数据物理块数@20，逻辑组数@24，扇区字节数@28，块字节数@32，组扇区数@36，CRC@252 |
| 组头 | magic@0，format@4，epoch:u64@8，逻辑组号@16，组版本:u64@20，七扇区CRC@28..55，页CRC@252 |
| 提交 | magic@0，format@4，epoch:u64@8，逻辑组号@16，组版本:u64@20，头CRC@28，提交CRC@252 |

| 断电可见状态 | 解释依据 |
| --- | --- |
| B新PREPARING已验证、A尚旧 | 最新epoch已出现，旧READY不能掩盖；数据区尚不得破坏 |
| B与A同代PREPARING均验证 | 数据区破坏性擦除的前置证明；阶段各占新页，卷头块擦除需全块验证 |
| 全数据区擦除验证、B READY有效、A仍同代PREPARING | 格式化已完成，可依READY恢复，即使调用者尚未收到成功 |
| B与A READY均验证 | 格式化调用可确认成功 |
| 无有效卷描述 | UNFORMATTED，即使有不可解析残片；不授权自动格式化 |
| 最高epoch仅PREPARING / 格式或几何不符 | 分别INCOMPLETE / INCOMPATIBLE |
| 同组同版本两个有效提交 / 获选头或数据损坏 | CORRUPT |
| 提交CRC无效 | 按未提交处理；不能分辨撕裂写与事后提交页损坏 |

旧失效记录可能已擦坏头而残留提交页；故选最新版先用独立提交CRC，再验证获选整块。空头/提交页不是全块擦除证明。未映射扇区值为0xFF。未确认组更新重启后可见旧版或完整新版，已确认组更新在本模型内持久；跨组可能部分提交。

故障模型只覆盖擦除值0xFF、1→0编程、页边界及撕裂写/擦除，重启不信任RAM。CRC存在碰撞，不保证任意欠压或电气损坏可恢复；控制器Abort不取消NOR内部写擦，复位不能代替真实断电验收。板级证据缺口见 [#9](https://github.com/immorcoding/mp3_project/issues/9)。

# Storage · 曲库与窗口参考

[Storage 规则](storage.md#catalog) 的技术参考；接口签名与当前容量查 [Storage Task README](../../APP/tasks/storage/README.md) 和 `storage_catalog_config.h`，不在此复制 API 表。

## 曲库、顺序与代次

曲库由 Storage Task 私有 `catalog/` 管理。扫描只经 Filesystem 卷感知目录接口读取 SD `Music/`，Flash、卡根与安装暂存目录均不进入曲库。条目存 UTF-8 相对路径的字符串池偏移/长度，不存卷字段、标题或封面。

播放列表是曲库下标序列，当前顺序表为恒等映射；有效长度取建表时曲库条数。游标是当前播放列表下标，与窗口起点使用同一坐标系但各自保存。非空重扫后游标从 0 起，空库或作废后无当前曲；上一首/下一首环形移动，点按只改游标，尚不打开或解码文件。以后随机/心动顺序改变序列，不因此重扫盘。

内部 `.bss` 计数驱动曲库代次；SDRAM NOLOAD 表中的代次只是副本。扫描重置表头，不清整池；启动不把 `.storage_catalog` / `.music_sheet` 当 `.bss` 清零。作废曲库时递增代次、清有效条数，同时将播放列表代次置 0 并作废游标；不必清数组。

## 扫描结果

挂载成功后扫描；拔卡先作废曲库，再卸载。递归扫描一次只开一个目录句柄，收录 `.mp3` / `.MP3`，跳过点开头名；深度、条目数、字符串池上限由配置给出。

| 条件 | 结果 |
| --- | --- |
| 未插卡或根 `Music/` 打不开 | 空库；根目录打开失败当前按成功空表处理，不自动创建目录 |
| 条目或字符串池耗尽 | 保留已扫描部分，截断后成功 |
| 深度栈满 | 跳过该子目录并告警 |
| 读目录或关目录失败 | 扫描失败 |

## 窗口交接

窗口单槽依次经历 `IDLE → PENDING → READY → IDLE`。GUI 仅在 SD 已挂载且不在消抖中、槽为空闲时提交起点 `Index`、请求条数 `Length` 和代次，不提交路径。Storage 填充这一窗，将 `Length` 改为实际条数；`Buffer[i]` 对应播放列表 `Index+i`。代次不匹配返回代次 0 的空窗。GUI 校验代次、整窗消费后释放槽；高亮还需比较游标代次。`Service/gui` 接受 APP 翻译后的展示数据，不包含 `storage_listbuffer.h`。

Queue 使用固定 panel 槽重用窗口，不取得整表，不把单槽改成环形数组。竖滑按滚出顶部的整行移动起点，除首窗外保留一行回滑余量；短末窗停止向外推。换窗扣除整行高度、保留像素余量，不按 MainPager 的整页吸附处理。GUI 布局事实由 GUI area 管理。

## 元数据扩展边界

当前窗口显示原始曲库路径，歌手为空；这不等于已解析的标题。GUI 不裁路径、扩展名或按 ` - ` 伪造元数据。后续由 MP3 解析 Component 识别 ID3/音频载荷，解码 Component 将音频载荷变 PCM；`Components/audio` 只是 PCM 发送。

标签在 Storage 填窗时按曲库路径按需读取，不在全库扫描时建立标题池；窗口可演进为标题/歌手载荷，GUI 仍只显示结果、不打开文件。缺标签/读失败的替代文本由加载/解析侧决定，封面属于 Now Playing。Books 扫描、随机/心动、Playback 打开与解析尚未实现，不据此创建空 Module。范围背景见 [ADR-0015](../adr/0015-volume-roles-and-resource-install.md)。

# Storage · FTL 提交与恢复参考

[Storage](storage.md#durability) 的技术参考；格式字节与卷几何另见 [FTL v1](storage.ftl-format.md)，物理分区见 [介质参考](storage.media.md#物理分区)，接口见 [Component README](../../Components/flash_ftl/README.md)。

## 组更新与确认

每个七扇区逻辑组的一个版本独占 4 KiB 擦除块。局部写入先读旧组保留其他扇区，整组覆盖可略过旧读取，同一请求的同组修改合并。未映射部分填 `0xFF`。

1. 分配确认全块已擦除的新块；不足则推进 GC，不能擦当前有效块腾空间。
2. 写头及数据，每页在本擦除周期最多编程一次。已确认擦除块可跳过全 `0xFF` 数据页，但仍计算 CRC 并读回验证。
3. 读回校验头与完整数据，再最后写提交页、等待并验证。
4. 切换 RAM 映射、将旧块标为可回收，才确认组完成；不回写旧块失效标志。

跨组逐组提交，失败前可能已有组生效；未确认请求重启后可见旧版或完整新版，已确认数据须满足故障模型内持久性。没有仅写 RAM 就早确认的缓存。Sync 确认既有写入和硬件安全，不要求清空所有 GC。

## 双卷头与扫描

前两块 A/B 是卷描述专用块。重新格式化顺序为：保留旧 A，在 B 建立并验证新 epoch PREPARING → 在 A 建立并验证同 epoch PREPARING → 擦除并验证整个数据区 → 追加验证 B READY → 追加验证 A READY → 报成功。阶段写不同页，不原地随意改状态。两份 PREPARING 均验证前不得破坏数据区；每个卷头块擦除后也验证全块，防旧 READY 残留。

恢复选可验证最高 epoch。最高 epoch 只有 PREPARING 表示未完成，旧 READY 不能覆盖它；B READY 与同代 A PREPARING 可证明格式化完成，故调用者没收到成功不等于介质没变化。FTL 格式化与随后 FatFs 建 FAT 是两层操作。

每次 Open 重建 RAM 表，不信任 NOLOAD 残留。先扫描头/提交页，以提交页独立 CRC 筛选当前 epoch 并选择最高组版本，再读取获选完整块检查头、绑定和数据。旧失效块可能已被 GC 擦坏头而留下提交页，不能在选最新版前因此误报损坏；最新已提交数据损坏必须报错。空头/提交页不足以证明全块擦除。

## GC 与内存

循环分配游标找已擦除块，循环 GC 游标找失效块。旧组整块失效，普通 GC 无需搬迁有效扇区；未提交/中断擦除块只有恢复确认不承载当前数据后才可回收。

预留预算是全池容量份额，不是固定地址区；空闲数只计已确认擦除块。启动/停止水位有滞回，以预留预算为分母，保护下限另算。前台分配触及下限先 GC，无安全空间报错；无可回收块结束，不忙循环或擦有效块。Storage 提供有限工作机会，一次最多回收一块，不承诺 NOR 擦除可抢占。比例和周期现值查配置，不维护第二份数字表。

Platform 注入 SDRAM NOLOAD 的映射/版本/状态表，以及 DMA 可达内部 SRAM 的工作区和校验区；后两者独占完整 32 B Cache line，同时只运行一个操作。表按数据物理块容量预分配，避免 Platform 依赖 FTL 私有预留比例。扫描只复用工作区，不拷整片进 SDRAM。启动摘要可含 epoch、有效组、空闲/失效块与扫描耗时；诊断日志开关不改变执行和错误。

不做静态磨损均衡、冷数据搬迁或持久化擦除计数。游标丢失不影响恢复，但频繁重启可能造成磨损偏向；本次上电统计不是累计寿命保证。

## 推进、超时与安全恢复

Process 的软件可继续阶段不能一律 BUSY 后睡眠；只在等待硬件时等待通知并设置超时唤醒。Platform 对原始操作推进 W25Qxx，对 FTL 操作只推进 FTL，由 Bridge 推进底层，不重复推进。页完成不是整笔完成。

参数错误拒绝请求但不破坏正常状态，在飞请求返回忙。提交前校验失败保留旧映射并停下，不自动换块重试；超时/介质错误停止受理并保持故障。控制器 Abort 不取消已发出的 NOR 内部写擦；只有 Quiesce 确认控制器/DMA 不再访问缓冲，才可返回并复用。无法确认时持续隔离/等待，极端情况需板级看门狗或复位策略。

显式恢复先确认硬件安全与 WIP=0/QE，再扫描，旧 FatFs 对象失效。提交成功但通知丢失可对调用者报失败，因此失败不证明没有写入。整笔 FTL 请求内映射保持关闭；成功且空闲才按入口状态恢复，失败不恢复。资源消费者不能同期读映射窗口。

## 验证边界

算法或故障语义修改至少覆盖：

- 首尾/越界/溢出、单扇区/整组/跨组、局部保留、未映射值和跳页校验。
- 头、每个数据页、提交和回读前后掉电；新写失败保留旧映射，跨组部分提交。
- A/B PREPARING、数据擦除、B/A READY 各阶段掉电；epoch、同版本歧义、几何不兼容、空头非空块。
- 最新已提交数据 CRC 错误不回退；GC 水位/下限、无失效块、擦除中掉电、持续覆盖。
- 通知丢失/延迟、超时、DMA 中止失败、NOR 仍忙；缓冲与映射不得提前归还。
- USER LUN/盘符、安全弱默认/强覆盖、CubeMX 薄接缝，以及 FatFs 同步后重挂载内容校验和独立 SD 回归。

Fake NOR 模拟擦除值 `0xFF`、仅 1→0 编程、页边界及撕裂写/擦除，重启清空 RAM。CRC 有碰撞且不能区分撕裂提交与事后提交页损坏，不能承诺任意欠压/电气损坏可恢复。复位不能替代真断电，单组原子不等于文件事务原子；耗时/容量/恢复的实测证据留 ticket，板级缺口见 [#9](https://github.com/immorcoding/mp3_project/issues/9)。

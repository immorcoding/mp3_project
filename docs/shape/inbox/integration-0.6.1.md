- Signal（friction · GUI-4，2026-10-22）：#106 grilling 判定「现有基线帧不变」，实施后 12 个场景 50 帧哈希仍变。根因（已实验验证）：LVGL v8 在动画链表为空时暂停动画定时器，`lv_timer_resume` 不重置节拍，新动画首拍相位随之改变；Lock 呼吸不再常驻后，唱盘角度、状态行闪烁透明度、翻页回弹位置的采样相位变化。验证：在模拟器临时加一条常驻空动画，12 个场景全部回到旧哈希；逐帧像素差只落在唱盘圆盘、状态行（字形相同、透明度不同）与 pager 左缘 6 px 的回弹条内。按 GUI-4 看图后 `-Update` 重录。教训：任何改变「是否有动画常驻」的改动都会移动其他动画的采样相位，grilling 判「基线不变」时应考虑这一点；未用常驻空动画规避，因为它会让模拟器偏离产品的空闲行为并污染动画数断言。
- 风险（hw:pending，#107 评审核对，2026-10-22）：500 ms 超时后迟到的 SDMMC DMA 完成事件是否会被下一次传输误当作完成。代码核对：`filesystem_sd_transfer_finish` 超时只调 `Platform_SD_CompleteTransfer(ERROR)` → `SDCard_FailTransfer`，把 Device 置 `ERROR`（或 `NOT_PRESENT`），不中止 HAL/SDMMC 的在途 DMA；`SDCard_Start*Blocks` 要求 `State == READY`，ERROR 态下后续传输被拒，只能经 `SDCard_Init`（Port DeInit/Init）恢复。`filesystem_sd_transfer_prepare_wait` 在每次启动前清通知挂起位，覆盖「迟到事件先于下次 Start 到达」。残余窗口：迟到完成 IRQ 落在恢复之后、下一次 `prepare_wait` 之后——只有 Port DeInit/Init 未复位 SDMMC/DMA 在途传输时才可能发生；通知值不带流水号，无法在 `wait` 里区分。代码与主机测试无法证实，需上板：构造超时（如拔卡/低速卡）后恢复并紧接读写，确认无误完成与数据错位；若成立，给通知加传输序号或在恢复路径显式 Abort DMA。

- 2026-10-17 · architecture · signal · 无对应规则 · #71 K1/B9 要求状态机不依赖 FreeRTOS。`storage_audio_stream.h` 为 `TaskHandle_t` 包含 FreeRTOS 头，所以状态机没有直接使用 `Storage_Audio*TypeDef`，而是在 `playback_machine.h` 自带一组 1:1 对应的请求、记录、结果、终止与块视图类型（`Playback_Machine*TypeDef`）和 `Playback_MachineOpsTypeDef`，由任务外壳（#80）映射到 `storage_audio_stream_*`。代价是类型重复、有漂移风险；#80 可以在外壳里用 `_Static_assert` 固定枚举值一一对应，或把 Storage 的请求/记录类型拆到不含 FreeRTOS 的头里让两边共用——后者要改 #75 已合入的公开头，本票没有做，请 drain 时决定。
- 2026-10-17 · architecture · signal · K3 · K3 没有规定“曲目数 N 未知”时 NEXT/PREV 的行为（开启 OK 之前、或 SELECT 换了代次之后）。本票的选择：N 未知时 NEXT/PREV 被忽略（仍回显命令序号），因为无法环形步进，也不能让游标越过末曲；SELECT 代次不变时沿用已知 N，换代次则置未知直到下一个开启 OK。若 K3 想要“排队等 OK 后再步进”，需要补写；主机测试 `playback_task_cursor` 把当前选择固定了下来。
- 2026-10-17 · architecture · signal · 无对应规则 · 命令表“停止”一列必须有进入停止态的出口才可测，而 B6 的停止原因表归下一票（#79）。本票只把流记录中的 READ_ERROR（保留游标）接到 `enter_stopped()`；其余开启结果与终止事实（NOT_READY、STALE、NO_TRACK、BAD_FILE、IO_ERROR、CARD_REMOVED）、播放模块与 Platform 的故障、T_data/T_out、AUDIO_FAULT 锁存规则、`SkippedBadCount` 都留给 #79，现在状态机对它们不作反应（流会停在“开启中”，新命令照常取代它）。#79 接入时 `enter_stopped()` 已有 `keep_cursor` 参数，可直接复用。
- 2026-10-17 · harness · signal · 无对应规则 · 假播放模块（`Tests/playback_task/playback_task_test_support.c`）是 `Service_Playback_*` 的简化模型：按窗口字节数、每帧字节数、每次推进帧数解码，暂停且已解码满 2 帧（两个半区的预填折合）后不再解码，`fake_player_release_tail()` 之后输入读尽且窗口空才回报 `StreamEnded`。它不模拟 Platform 半区、欠载与 Stop/Start 的顺序（那是 `Tests/playback_service/` 的职责），所以本模块的 PASS 只证明状态机对播放模块 Interface 的使用顺序和对回报事实的反应，不证明两者拼起来出声。
- 2026-10-17 · hardware · cite · 无对应规则 · 状态机在一次唤醒内调用 `PauseOutput`/`AbandonStream`（同步 Platform Stop，约 14 ms 上界）与 `Pump`（可能 Start）；B1 的“单次唤醒最长执行时间 ≤ 6 ms（不含 Stop/Start）”板级验收项仍然 `hw:pending`，主机测试不度量时间。

- 2026-10-26 · resources/container · proposed · RES-9 补一句：Component 除解码 Metadata 外，还公开 `ResourcePack_LocateFontBin()` 给出 bin 的 head、cmap、loca、glyf 分段范围与 head 参数（`ResourcePack_FontBinLayoutTypeDef`，不依赖 LVGL），字体消费者在其上解析字形、cmap、kern 与位图；字形表与位图重排仍由消费者负责。_Why:_ 分段框架与 head 校验只保留一份实现，Component 的 Metadata 核对与消费者的解码对 bin 的结构认定不会分叉。_Source:_ [0.7.0 spec](https://github.com/immorcoding/mp3_project/issues/112)、#119。
- 2026-10-26 · gui/music · proposed · GUI-22 补一句：字体解码把 `lv_font_conv` 的 FORMAT0 cmap 子表一律输出为 SPARSE 子表。_Why:_ LVGL 8.3.11 的 `get_glyph_dsc_id` 用 `rcp > range_length` 判断范围，码点恰为范围末尾的下一个时，FORMAT0_TINY 返回邻近字形（按代码推得，真实字体里 U+007F 会得到 `¤`；未在 LVGL 上运行验证），FORMAT0_FULL 多读列表外一项；字集外紧邻范围末尾的字符因此会画成另一个字而不是占位框，与 GUI-22 “缺字画占位框” 相悖。稀疏表二分查找不受影响，代价约 19 KB。_Source:_ `Service/gui/font/README.md`、`Tests/gui_font`（`gft_glyph_id` 复刻 LVGL 的查找写法并断言这些码点得到 0）。

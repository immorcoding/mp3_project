# Inbox: ticket/77-playback-output

> 以下是 2026-10-17 实施 [#77 播放模块（二）：PCM 半区与输出管线](https://github.com/immorcoding/mp3_project/issues/77) 时记下的 Signal，规则正文的改写尚未批准。drain 时提给用户。

- 2026-10-17 · hardware · signal · HWD-6、HWD-2 · PCM 两个半区（9216 B）需要 AXI SRAM NOLOAD 段，而 `stm32h743zgtx_flash.ld` 受 CubeMX 守卫（ARC-2），本票未改。半区暂借链接脚本现有的 `.sd_dma_buffer`（AXI SRAM、NOLOAD、32 字节对齐），段名在 `Service/playback/playback_service_config.h` 的 `PLAYBACK_SERVICE_PCM_SECTION`。待用户授权后新增独立的 `.playback_pcm (NOLOAD) >RAM` 段，再只改该宏（#75 的块池对 `.storage_catalog` 做了同样的处理）。HWD-2 审查：半区内容 `Service_Playback_Init()` 写 0，首次 `Start` 之前一定被预填完整覆盖；AXI SRAM 无 SDRAM 全容量诊断。
- 2026-10-17 · architecture · cite · ARC-18 · PCM 半区的所有权在实现里按时段转移：预填由播放模块写、Start 视两个半区已提交并 Clean；运行中半区释放后由播放模块补满并 `SubmitHalf`；`Stop` 返回 OK 后交还；`Stop` 失败锁存 STOP_FAILED 后模块置 `Faulted`，不再写任何半区、不再 Start/Submit（主机测试覆盖暂停、欠载恢复、流尾和放弃四处 Stop 失败）。规则表述与实现一致；architecture.md Open questions 里关于 ARC-12 音频流专用交接与 ARC-18 的“过渡说明（2026-10-09）”要在后端 spec 的最后一张票（播放任务）落地后再删，本票只完成了 ARC-18 的 Service 侧。
- 2026-10-17 · architecture · signal · 无对应规则 · #71 D12 把 `Service_Playback_*` 的具体名字留给实施票，本票定为 `Service_Playback_Pump()`（推进输出管线并返回事实）、`PauseOutput()`、`ResumeOutput()`、`AbandonStream()`；事实分“事件”（只在发生的那次推进里给出）与“状态”（条件持续时每次推进重复给出：`SyncExhausted`、`StreamEnded`、`StartRejected`、`TransferError`、`StopFailed`）。播放任务（#71 B1）只用输出管线；解码半边的 `Advance`/`ReadFrame` 在一条流被 `Pump` 驱动之后返回 `SERVICE_BUSY`，避免两条路径同时消费输入窗口。若 spec 想让 `Advance` 直接承担推进（D12 字面“推进（解码、填半区、提交、处理欠载，返回事实）”），需要改写 #76 已合入的解码半边测试，故本票没有这么做，请 drain 时确认。
- 2026-10-17 · architecture · signal · 无对应规则 · #71 D9/D8 的两处补充解释：(1) 暂停时 Platform 的释放数比补满数多出两个以上（连续欠载）时，按序补满会覆盖尚未重放的半区，实现改为丢弃半区、恢复时按解码进度整体重新补满；(2) 欠载恢复丢弃两个半区时，已写入但未提交的半区的一部分音频（至多约 24 ms）随之丢掉，已解码时间不回退。两者都发生在已经欠载、有爆音风险的路径上，属于听感代价，请板测时一并听。
- 2026-10-17 · harness · signal · 无对应规则 · 假 `Platform_Audio_*` 放在 `Tests/playback_service/fake_platform_audio.c`，按 `platform_audio.h` 与 `platform_audio.c` 的合同建模；DMA 读到的是 Start/SubmitHalf 时 Clean 的副本而不是实时内存，写了半区忘记提交的缺陷会在播放日志里露出。MPEG-2 夹具的 22.05 kHz 不在 Platform 支持的采样率内，为覆盖“非整半区的流尾补 0”，假对象提供 `fake_audio_accept_rate_for_test()`，只在该用例里放宽；这不改变生产合同，但是假对象里唯一不忠实于真实 Platform 的开关，审阅时请留意。
